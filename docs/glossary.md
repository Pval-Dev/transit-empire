# Glossary

This glossary explains the main technical and domain terms used in the Transit Empire documentation.

The goal is to make the project understandable to readers who may not know Unity, simulation systems, or airline management terminology.

## Core Terms

| Term | Meaning |
|---|---|
| Simulation | A software system that models changing state over time according to rules |
| Runtime | The period when the application is actively running |
| Orchestrator | A component that coordinates multiple systems or workflows |
| Manager | A Unity-style component responsible for a specific area of behavior |
| Domain entity | A runtime object that represents an important concept in the simulation |
| DTO | Data Transfer Object; a serializable object used to save or transfer structured data |
| State machine | A system where an entity moves between defined states based on conditions |
| Data-driven | Behavior or content generated from external data instead of being manually hardcoded |

## Unity Terms

| Term | Meaning |
|---|---|
| GameObject | Unity object that can contain components and exist in a scene |
| MonoBehaviour | Base Unity class used for scripts attached to GameObjects |
| Prefab | Reusable Unity object template |
| Scene | Unity runtime environment or screen |
| Transform | Position, rotation, and scale data of a GameObject |
| Component | Script or built-in Unity behavior attached to a GameObject |
| Collider | Shape used for click detection or physics interaction |
| SpriteRenderer | Component that displays 2D sprites |
| LineRenderer | Component that draws lines in the scene |
| Mesh | Geometry made from vertices and triangles |
| RenderTexture | Texture target used to render a camera view into UI |
| PlayerPrefs | Unity key-value storage for small persistent settings |
| Resources | Unity folder system used for runtime asset loading |

## Transit Empire Domain Terms

| Term | Meaning |
|---|---|
| Airline | The simulated company controlled by the user |
| Country | A purchasable territory containing airports |
| Airport | A network node that generates passengers and supports routes |
| Regional airport | Small/local airport type |
| Capital airport | Medium hub airport type |
| International airport | Large airport type with broader route potential |
| Route | A connection between two owned airports |
| Fleet | The collection of aircraft owned by the airline |
| Aircraft / Plane | Autonomous transport entity that operates routes |
| Garage | Local airport inventory where aircraft are stored |
| Equipped aircraft | Aircraft prepared for route assignment |
| Aircraft in route | Aircraft actively assigned to a route |
| Passenger demand | Stored passengers waiting for specific destinations |
| Inbound route | Route reference pointing into an airport from another origin |
| Route slot | Capacity limit for how many routes an airport can support |
| Runway capacity | Capacity limit for how many/what size aircraft can operate from an airport |

## Simulation Terms

| Term | Meaning |
|---|---|
| Game speed | Multiplier controlling how quickly simulation time advances |
| AdvanceDay | Daily simulation update handled by `GameManager` |
| Day duration | Real-time duration of one simulated day |
| Demand generation | Airport process that creates passengers over time |
| Boarding | Aircraft state where passengers are loaded |
| Flying | Aircraft state where it moves along the route |
| Arrival | Aircraft state where revenue, XP, and passenger redistribution are processed |
| Turnaround | Delay state before the aircraft begins the return trip |
| Out of service | Aircraft repair state |
| XP | Experience points used for progression |
| Stat points | Points spent to improve aircraft or airport stats |
| Maintenance | Recurring operational cost for airports or aircraft |
| Wear | Aircraft degradation over time and distance |
| Reliability | Aircraft durability/performance stat |

## Economy Terms

| Term | Meaning |
|---|---|
| CashMovement | Central method used to apply money changes |
| Revenue | Money generated by aircraft route operations |
| Expense | Money spent on purchases, payments, or maintenance |
| Daily income | Money earned during the current simulated day |
| Total earned | Lifetime income metric |
| Total spent | Lifetime expense metric |
| Net worth | Estimated company value from money, airports, and aircraft |
| Reputation | Market trust/quality metric affecting finance and performance |
| Autonomy | Company ownership/control value affected by investors |
| Loan | Debt product with remaining balance and daily payment |
| PerCapita loan | Loan based on current money |
| PerAvg loan | Loan based on average aircraft/route income |
| Investor | Capital provider taking a percentage of income |
| Financial penalty | System pressure caused by debt or missed payments |
| Government intervention | Critical financial consequence that resets debt and seizes assets |
| Aircraft seizure | Penalty where a percentage of aircraft are removed |

## Data Pipeline Terms

| Term | Meaning |
|---|---|
| CSV | Structured table data format used as an airport data source |
| GeoJSON | JSON format used for geographic boundaries |
| Preprocessing | Offline transformation of raw data before Unity uses it |
| airports.json | Unity-ready airport dataset generated by Python |
| countries.json | Unity-ready country geometry dataset generated by Python |
| Triangulation | Conversion of polygon geometry into triangles for mesh rendering |
| Country mesh | Filled country shape generated from triangle data |
| Border points | Points used to draw country outlines |
| Multipliers | Numeric values used to scale demand, price, or cost behavior |

## Persistence Terms

| Term | Meaning |
|---|---|
| Save slot | A numbered save file |
| Snapshot | Saved copy of runtime simulation state |
| Serialization | Converting runtime state into storable data |
| Deserialization | Loading stored data back into runtime objects |
| Multi-pass load | Loading process split into stages because objects depend on each other |
| Stable identifier | A saved name or key used to reconnect objects after regeneration |
| GameSave | Root save DTO |
| CountrySave | Serializable country state |
| AirportSave | Serializable airport state |
| PlaneSave | Serializable aircraft state |

## UI Terms

| Term | Meaning |
|---|---|
| HUD | Main on-screen operational dashboard |
| Contextual UI | Interface that changes behavior depending on current selected object or mode |
| Panel | UI group shown for a specific operation |
| Button builder | Script that creates UI buttons dynamically |
| Route mode | UI/system state where clicking an airport selects a route destination |
| Equip mode | UI/system state where selected aircraft can be equipped or assigned |
| Maintenance panel | UI listing unpaid airport maintenance |
| Slot selector | UI for choosing save/load file slots |
| Localization | Process of applying language-specific text |
| Safe area | Screen region safe from notches or rounded device edges |

## Architecture Terms Used In This Repository

| Term | Meaning In This Project |
|---|---|
| Core orchestration | `GameManager` coordinating global systems |
| Runtime domain | `Country`, `Airport`, `AirportGarage`, and `Plane` |
| Service layer | Cross-cutting systems like audio, notifications, localization, and settings |
| UI controller | Script that manages one interface context |
| World builder | Script that creates runtime world objects from data |
| Data pipeline | Python preprocessing plus JSON resources plus Unity runtime generation |
| Persistence layer | `SaveManager`, save DTOs, and JSON slot files |
